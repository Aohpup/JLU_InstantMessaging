# P3 运行、演示与备份

更新日期：2026-09-30。适用于已完成 P3 验收的控制台程序。

## 1 启动与保存

项目根目录的 PowerShell：

```powershell
cmake --preset local-debug
cmake --build --preset local-debug
.\build\debug\bin\jlu_im.exe
```

外部 PowerShell 可使用完整路径：

```powershell
& "D:\C_code\Cpp_test\JLU_InstantMessaging\build\debug\bin\jlu_im.exe"
```

如果提示缺少 MinGW DLL，先执行 `$env:PATH = "C:\mingw64\bin;" + $env:PATH`，再启动。外部 CMD 使用带引号的完整路径即可，不加 PowerShell 的 `&`；需要时用 `set "PATH=C:\mingw64\bin;%PATH%"`。

| 模式 | 参数 | 数据处理 |
| --- | --- | --- |
| 正常使用 | 无参数 | 项目 data/jlu_im.db；首次初始化，之后恢复 |
| 持久化练习 | `--database "完整路径或相对路径"` | 只读写指定库；相对路径按终端当前目录解释 |
| 演示内存 | `--demo` | 每次初始化演示数据，不读写数据库 |
| 空平台内存 | `--empty` | 空平台注册练习，不读写数据库 |
| 查看默认位置 | `--help` | 只显示说明，不打开数据库 |

登录前选 **4 保存数据**，登录后选 **10 保存数据**。登录后 0 只注销；回到未登录主菜单再选 0，保存成功后退出。新库首次包含 A—F 演示账号；例如 QQ 10001、微信 wx_20001，统一密码 `DemoOnly123!`。已有库不会再次覆盖为演示数据。

VS Code 的 `Debug jlu_im (GDB)` 为正常模式；`Debug jlu_im (演示内存模式)` 传入 --demo。复制 exe 不会改变编译时固定的默认库位置，移动项目后重新配置构建，或通过 --database 指定新位置。

## 2 可重复的人工演示主线

先在项目根目录选一个新的练习库文件名，例如：

```powershell
.\build\debug\bin\jlu_im.exe --database ".\build\debug\practice\P3演示1.db"
```

再次完整演示可换成 P3演示2.db，避免清理旧数据。演示过程中重启必须使用同一个文件名。

1. QQ 10001 登录，进“8 好友管理 → 4 修改我的备注”，给 10002 备注“同桌”。返回登录菜单。
2. 进“9 群管理”，选 QQ 1001，选 11 创建子群：号码 2001，群名“讨论组”，群主 10001，其他成员选 10002，再输入 0 结束并确认。返回并注销。
3. QQ 10004 登录，进入群管理选 2001，选 3 申请并确认，记下请求编号。返回、注销，然后在主菜单选 0 保存并退出。
4. 重新运行同一个 --database 命令。QQ 10001 登录，好友列表中的“同桌”仍在；选子群 2001，查看请求并同意。查询成员应看到 10004。
5. 切换到父群 1001，选 13 将模式改为微信并确认。查看子群列表，应为空。返回、注销、主菜单 0 保存退出。
6. 第三次启动同一个库，父群仍为微信模式，没有子群。切回 QQ 后仍没有旧子群；只有手动重新创建才出现。退出时保存。

这条主线展示“业务修改 → 保存 → 关闭程序 → 加载 → 继续业务”。完整账号绑定、双向备注、编号和失败检查可运行自动验收：

```powershell
ctest --preset local-debug
python tests/p3_acceptance.py
```

Python 只用于执行验收脚本，程序运行本身不依赖 Python。脚本只重建 build/debug/p3_acceptance 下的固定验证库，运行输入、输出和结果保存在同目录；其中不会读取或修改正式库的业务记录，仅核对正式文件前后校验值。

## 3 数据库备份与恢复

先在程序内保存成功并正常退出，确认没有另一个程序仍在写同一个库，再复制 `.db` 文件。当前程序不启用 WAL，正常关闭连接后，完整数据在该文件中。

项目根目录的 PowerShell 备份示例，日期或文件名可自行修改：

```powershell
New-Item -ItemType Directory -Path ".\backup" -Force
Copy-Item -LiteralPath ".\data\jlu_im.db" -Destination ".\backup\jlu_im_20260930.db"
```

无需覆盖正式文件即可检查备份：先复制备份为练习副本，再用 --database 打开副本。程序退出会保存，因此不要把唯一的备份当练习库修改。

```powershell
Copy-Item -LiteralPath ".\backup\jlu_im_20260930.db" -Destination ".\backup\恢复检查.db"
.\build\debug\bin\jlu_im.exe --database ".\backup\恢复检查.db"
```

确实要恢复到默认位置时，先退出程序、另存当前正式库，再用确认过的备份替换 `data/jlu_im.db`。本阶段没有自动替换用户数据库。不要删除正式库来“重新初始化”，除非确实准备丢弃其中的数据。

## 4 保存失败时

保存失败时当前修改仍在内存。可以修复文件占用或写入权限后重试，也可以返回菜单。只有明确选择“放弃未保存修改并退出”才按该选择丢弃当前修改。数据库保留上一次成功保存的状态。

如果输入流已结束，无法继续选择，程序尝试保存失败后返回错误码 1。强制关闭终端或结束进程不会触发正常退出保存，因此重要修改可先主动保存。
