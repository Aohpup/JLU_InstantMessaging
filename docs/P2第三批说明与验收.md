## 代码阅读顺序

| 文件 | 看什么 |
| --- | --- |
| [GroupMemberLJY.h](../src/domain/GroupMemberLJY.h) | 一个群内成员：账号编号、管理员标记 |
| [GroupLJY.h](../src/domain/GroupLJY.h) | 群号、服务、群主、成员列表、管理模式及预留父群编号 |
| [GroupPolicyLJY.h](../src/services/GroupPolicyLJY.h) | 共同的虚函数接口，两种派生策略给出不同判断 |
| [GroupManagerLJY.cpp](../src/services/GroupManagerLJY.cpp) | 创建群、按当前服务查询、检查成员资格 |
| [DemoDataLJY.cpp](../src/services/DemoDataLJY.cpp) | 使用账号、好友和群接口装入 A—F 及演示群 |

平台用 map 保存群，群用 vector 保存成员。GroupManager 直接持有 QQ 与微信两种策略，通过基类引用选择，不增加策略工厂或动态分配。群保存模式标识，策略不保存成员，所以更换所选策略不会改写成员数据。

成员查询通过一次会话接口返回群与成员账号，不增加查询结果包装类。演示初始化使用两个普通函数，无需增加初始化类。现有简体中文 // 注释、int 编号及简单内存密码风格继续保留。当前正式源码为 21 个类、4 个枚举。

## 已实现的边界

- 新群自动加入群主；初始成员必须有同服务账号，拒绝重复成员、重复群主及同服务重号。
- 微信初始成员不允许管理员标记；QQ、微博可设置演示管理员。
- 建好并检查初始群数据后再保存，输入不合法不留下半个群。
- 演示加载只允许空平台，重复调用或存在用户时拒绝，不能覆盖已有数据。
- 界面仅提供本人群列表和群资料、成员查询；非群成员不能读取群资料和成员列表。列表展示号码、用户昵称及群内角色。
- 策略已能判断 QQ 申请/审批、微信邀请、踢人、管理员和子群规则；这些是供后续业务调用的判断函数，本批没有申请、审批、踢人等菜单，也不会执行这些操作。
- QQ 本方案采用申请审批途径，邀请入口不开放；微信采用成员邀请途径。微博默认采用 QQ 规则属于本项目约定。
- 父群编号目前为 0；模式切换、子群及请求记录仍留后续批次，不宣称完整切换已经实现。
