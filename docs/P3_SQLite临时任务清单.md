## 一、目标与实现原则

把当前内存中的人员、服务账号、绑定、好友、群和请求保存到本地 SQLite 文件，下次启动恢复，继续使用原有业务类和控制台菜单。

- SQLite 是唯一存储方案。第一批已由助手接入官方 3.53.4 源码和 CMake；用户无需安装数据库服务或手动创建正式项目数据库。
- 采用官方合并源码 `sqlite3.c` 与 `sqlite3.h`，将 C 源码编译成库，再链接到 C++ 程序。CMake 已启用 C 和 CXX，第三方文件与自写源码分开。
- 第二批已新增 `SqliteStorageLJY.h/.cpp`，集中处理连接、建表、保存、读取和错误。不增加 Storage 基类、ORM、连接池或多后端框架。
- 平台仍拥有内存数据；业务规则仍由现有管理类执行；存储接口不写在窗口或控制台输入逻辑里，方便 P4 共用。
- 优先实现“启动读取、明确保存、正常退出保存”。课设数据量小，先在一次事务中保存完整平台状态，不同时维护复杂的逐条增量同步。
- 不保存当前会话和本次运行的密码登录历史，重启后仍需登录。已有 MySQL84 不参与运行，不修改系统服务。
- 保持普通整数编号、LJY 类名后缀与简洁中文 // 注释，重点说明接口，不逐行注释。

## 二、SQLite 接入原理

编译时：`sqlite3.c → SQLite 库 → 与项目链接 → jlu_im.exe`。

运行时：`控制台 → 会话/业务 → PlatformLJY 内存数据 ↔ SqliteStorageLJY ↔ data/jlu_im.db`。

`sqlite3.h` 提供函数声明，`sqlite3.c` 实现数据库引擎；`SqliteStorageLJY` 调用这些函数执行 SQL。`.db` 是保存数据的文件，不是源码或可执行程序。SQLite 在本程序进程内读写文件，不需要另一个数据库服务器进程。

启动时把表记录还原成当前实体与容器；运行时仍操作内存；保存时将内存状态写回表。事务保证一次保存中的关联数据一起提交；失败时回滚，不能留下只保存了群却没保存成员的状态。命令行工具 `sqlite3.exe` 仅供人工查看或练习，程序通过库函数操作数据库，不启动它来执行 SQL。

### 顺序 4：完整事务保存

完成标准：一次保存得到完整状态；失败时磁盘保留上一次成功版本，内存中的当前修改仍可重试保存。先做整批保存，不加自动迁移或备份框架。
