## 修改结果

| 用户要求 | 当前行为 |
| --- | --- |
| 已有好友立即提示 | 输入号码后即检查，重复好友、自己或不存在的账号不会进入确认 |
| 不切换到本身 | 当前 QQ 再选 QQ 等情况提示“当前已在该服务中，无需切换”，登录状态不变 |
| 已绑定优先提示 | 登录 QQ 时提示“QQ 账号已绑定”，登录微信时提示“微信账号已绑定”；不再要求先登录另一端 |
| 不可移除自己 | 有管理权限的用户输入自身号码后立即拒绝，不进入确认；普通成员更早被权限检查拒绝 |
| 先选群再操作 | 群管理先显示我的群列表并读取群号；存在才显示操作菜单，选 1 可切换群聊 |
| 先显示成员 | 移除成员、任免管理员和转让群主前显示成员号码、昵称、身份，再读取目标号码 |
| 不直接移除管理员 | 群主必须先取消目标管理员身份，再移除；业务接口也遵守同一规则 |
| 具体权限原因 | 区分管理员不能移除群主、管理员不能移除管理员、普通成员无管理权限、微信仅群主可移除等情况 |

## 新操作顺序

登录 → 9 群管理 → 输入有效群号 → 选择该群的操作 → 必要时选择目标 → 确认。

选群入口自动展示已加入的群，也允许输入尚未加入的群号，以便申请入群或处理收到的邀请。不存在的群号立即报错，不出现群操作菜单、目标账号提示或确认。选群不会让非成员读取成员资料。

选群后的选项 2—10 保持原编号；1 改为切换群聊，0 返回主菜单。退群成功后自动返回选群入口。查看和处理申请/邀请只针对当前群，输入其他群的请求编号会在同意/拒绝选择前被拒绝。

例：A 的 QQ 10001 登录，选 9 → 1001 → 8 → 10002，会提示先取消管理员身份；选 9（群内任免管理员）→ 10002 → 2 取消 → 1 确认，然后选 8 → 10002 → 1 确认，即可移除。各步骤取消均不修改数据。

## 实现位置

- ConsoleAppLJY：选群循环、成员展示、输入后检查及确认。
- SessionManagerLJY：好友候选检查、当前服务重复切换检查、已有绑定优先提示及当前群请求筛选。
- GroupManagerLJY：checkOperation 共用具体权限与目标检查，checkRequest 检查请求所属群、身份及状态；实际提交仍调用同一套规则。
- QQGroupPolicyLJY：群主也不能直接踢管理员。
- GroupOperationLJY：六种操作的普通枚举，使业务检查不依赖菜单数字；未引入新管理类或通用审批框架。
