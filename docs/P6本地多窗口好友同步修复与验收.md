# 本地多窗口好友申请同步修复与验收

日期：2026-10-27。适用：新版图形客户端打开同一个 SQLite 业务数据库。此次为现有功能修复，不改变 P6 批次完成状态。

## 1 问题与原因

A 窗口发送申请，B 窗口同意后，B 的好友关系和申请状态已经保存，但 A 仍显示待处理。原先每个进程仅在启动时加载一次 Platform，界面刷新只是重新读取自己的内存，没有重新读入其他进程的提交。

另一个相关问题是业务保存采用整个平台快照：A 如果随后保存旧内存，可能把 B 已处理的申请及新好友关系覆盖回旧状态。因此本次同时处理读取同步和旧副本保存，不能只改列表上的提示词。

## 2 修复方式与代码阅读

1. `schema/create_tables.sql` 的 `id_state` 增加 `revision`。仍然是十张业务表，不增加同步服务器。旧库由 SqliteStorage 构造函数自动补字段，不删除记录。
2. `SqliteStorageLJY::load` 读取同一事务中的业务数据和版本。`refreshIfChanged` 只在业务版本变化时重读，保留本次运行的密码登录历史。会话继续按原人员和账号编号工作，旧对象指针不能跨刷新保留。
3. `SqliteStorageLJY::save` 在写事务锁内检查当前版本，匹配才保存并递增版本。旧副本拒绝写入，不覆盖其他窗口的处理结果。聊天记录写入不递增该版本，不会每来一条消息都重建业务列表。
4. `main_gui.cpp` 向 MainWindow 注入保存及同步回调；`MainWindowLJY` 每 500 毫秒检查一次。收到新版本后刷新好友申请、好友列表、消息联系人及其他业务显示，更新角标。
5. 有未保存的内存业务修改时暂缓后台重读；内置确认卡片打开时也暂缓，避免嵌套事件循环使正在操作的对象引用失效。好友备注及同一群的子群创建表单保留未提交草稿。
6. 两端恰好同时提交时，后提交的旧副本会被拒绝。窗口重读已提交数据，红色提示“其他窗口已更新数据，现已同步。刚才的操作未保存，请重新操作。”不会把未保存的操作冒充成功，也不无限重试覆盖。普通磁盘写入失败仍保留内存修改供重试。

推荐阅读：SqliteStorageLJY.h → .cpp 的 readRevision、refreshIfChanged、load、save → main_gui.cpp 的两个回调 → MainWindowLJY::synchronizeExternalChanges 与 save → FriendsPageLJY::refresh。

## 3 实际验收

使用 `tests/p6_shared_business_gui_tests.cpp` 启动两个独立 GUI 测试进程，各有独立 Platform 和 SQLite 连接，共用临时库；操作真实页面控件，不接触日常数据。

| 场景 | 结果 |
| --- | --- |
| A 发送申请，已经打开的 B 自动看到待处理 | 通过 |
| B 点击同意，A 自动变为已同意 | 通过 |
| 双方好友列表及 A 的聊天联系人包含新好友 | 通过 |
| 同步后仍保持登录，未提交的好友备注与子群草稿不丢失 | 通过 |
| 旧库没有 revision 字段，重新打开后自动补齐 | 通过 |
| 未同步的旧平台保存被拒绝，处理结果仍在数据库中 | 通过 |
| 没有业务变化不重读，其他表写入不触发业务同步 | 通过 |

另外通过原有 `p3_storage_load`、`p3_storage_save`、`p4_friends_gui`、`p4_friends_reload`、`p4_subgroups_gui`、`p4_subgroups_reload`，合计本次运行的七个不同 CTest 测试全部通过。存储往返比较补入好友申请表，并排除每次递增的 revision 元数据，仍比较所有业务字段。

复测命令（先构建对应测试目标）：

```powershell
ctest --test-dir build/gui-debug -R "^(p6_shared_business_gui|p3_storage_save|p3_storage_load|p4_friends_gui|p4_friends_reload|p4_subgroups_gui|p4_subgroups_reload)$" --output-on-failure
```

## 4 使用范围

关闭旧窗口，两个窗口都使用更新后的程序，确认窗口底部的数据库完整路径相同。正常使用时约半秒更新；确认卡片打开期间等待当前操作结束后再同步。

不同路径的 .db 是不同业务数据源，不能仅靠相同账号号码自动合并；`--demo`、`--empty` 是各自独立的内存练习模式，不参与数据库同步。本修复不增加跨电脑账号同步服务。旧版程序不认识业务版本，勿与新版同时编辑同一个库。

本次不修改用户数据库中的好友关系或聊天记录；真实使用库仅在用户启动新版后执行补字段升级。已有被旧程序覆盖的历史状态不会由此次修复凭空恢复。
