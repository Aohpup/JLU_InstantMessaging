## 数据库是怎样搭起来的

### 1. 先把数据库引擎编进项目

CMake 新增的核心关系为：

```cmake
project(JLU_InstantMessaging VERSION 0.1.0 LANGUAGES C CXX)
add_library(sqlite3 STATIC third_party/sqlite/sqlite3.c)
target_include_directories(sqlite3 SYSTEM PUBLIC "${CMAKE_CURRENT_SOURCE_DIR}/third_party/sqlite")
target_link_libraries(jlu_core PUBLIC sqlite3)
```

SQLite 用 C 编写，所以新增 C 编译器；业务仍使用 C++17。STATIC 表示先生成静态库，MinGW 下文件为 build/debug/libsqlite3.a。include 目录解决编译器寻找 sqlite3.h 的问题，link 解决函数实现从哪里来的问题。主程序构建依赖已经接好，但它本批还没有调用存储接口。

### 2. 打开数据库文件

验证程序调用 `sqlite3_open(文件路径, &db)`。文件不存在时会创建；已经存在时打开。父目录由验证程序先创建。这里 db 是数据库连接句柄，不是某张表。

验证文件固定为 build/debug/p3_batch1/smoke.db，与正式项目数据隔离；运行目录变化不会让该验证程序误建另一个文件。

### 3. 建表

验证程序用 ifstream 读取 schema/create_tables.sql，再交给 sqlite3_exec 执行。以人员表为例：

```sql
CREATE TABLE IF NOT EXISTS persons (
    person_id INTEGER PRIMARY KEY,
    name TEXT NOT NULL,
    birth_date TEXT NOT NULL,
    location TEXT NOT NULL
);
```

这就是在数据库文件中建立一张有四列的表。INTEGER 是整数，TEXT 是文本，PRIMARY KEY 是唯一编号，NOT NULL 表示这一列不能缺值。IF NOT EXISTS 允许重复运行时保留已有表，它不代表数据库会自动升级表结构。

人员与账号通过 person_id 关联；账号与群成员通过 account_id 关联。表与所有字段的对应关系见 [数据库表设计](P3数据库表设计.md)。

### 4. 写入、读取与释放

验证中使用 `sqlite3_prepare_v2 → sqlite3_bind_text → sqlite3_step → sqlite3_finalize` 写入演示姓名。SQL 中的 `?` 是占位符，实际文本通过 bind 传入。查询 SELECT 后，用 sqlite3_column_text 读取结果。所有语句结束后调用 sqlite3_close 关闭连接。

本批没有建立正式存储类；第二批会把通用连接和执行过程整理进 SqliteStorageLJY，并实现完整事务保存。没有调用 sqlite3.exe，也不需要 MySQL 服务。

## 你可以怎样运行

在项目根目录的 PowerShell 执行：

```powershell
cmake --preset local-debug
cmake --build --preset local-debug
.\build\debug\bin\p3_sqlite_smoke.exe
```

最后一条单独运行本批验证程序；它会创建或打开验证库，维护编号为 1 的演示人员行，不写正式平台数据。输出应包含：

```text
SQLite version: 3.53.4
Database: D:/C_code/Cpp_test/JLU_InstantMessaging/build/debug/p3_batch1/smoke.db
Stored name: SQLite演示同学
PASS open, nine-table schema, bound insert, foreign key, reopen/select and close.
```

仅检查本批可用 `ctest --preset local-debug -R p3_sqlite_smoke -V`。若普通终端提示缺少 MinGW DLL，使用项目已配置终端，或临时执行 `$env:PATH = "C:\mingw64\bin;" + $env:PATH` 后运行。

不需要手动新建 .db 空文件；让 sqlite3_open 和建表 SQL 完成即可。数据库是二进制文件，不要当作普通文本修改。当前库只写入一名演示人员及编号状态，其余表尚无业务数据。
