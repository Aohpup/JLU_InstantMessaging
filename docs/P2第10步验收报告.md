## 4 真实 Windows 控制台检查

除输入输出管道流程外，复用原生控制台驱动：使用 Windows 控制台输入缓冲区发送按键，向实际进程发送 Ctrl+C。以下结果均通过：

- 密码使用星号占位，注册和登录密码不额外回显；演示密码说明仍正常显示。
- Ctrl+C 不结束菜单、资料输入、密码输入、确认或暂停中的程序。
- 成功与整项失败显示 `>>>按任意键继续`，返回菜单不增加多余暂停，Ctrl+C 不跳过暂停。
- 无效群号在选群时立即拒绝；自我移除、直接移除管理员在输入目标后立即拒绝；输入目标前展示成员。
- 取消管理员变更保持原身份；子群创建与模式切换可通过按键完成，取消不提交，切回 QQ 后管理员身份恢复。

记录：[P1 原生控制台](P2验收记录/P1原生控制台.txt)、[P2 原生控制台](P2验收记录/P2原生控制台.txt)。这些检查使用真实控制台 API，但不是人工点击 VS Code 终端；选中文字后的复制由终端负责，本轮没有重新验收终端的鼠标选择与复制操作。

## 5 菜单与课程规则核对

| 核对项 | 当前行为 |
| --- | --- |
| 菜单返回 | 主菜单 0 退出；登录后 0 统一注销；好友/群菜单 0 返回；群内 1 重新选群；退群成功后重新选群 |
| 输入取消 | 常规输入 0 返回；子群成员选择的 0 表示结束选择，随后仍需确认创建 |
| 先检查再确认 | 重复好友、当前服务重复切换、已有绑定、无效群号和目标权限在相应输入阶段提示 |
| 群规则 | QQ 申请审批、群主管理员管理；微信邀请接受、仅群主有管理特权 |
| 子群 | 顶级 QQ 风格群主创建一级子群；成员来自父群，退群/踢人保持父子一致 |
| 动态模式 | 保留成员及原始标记，只切换规则；微信模式暂停管理员权限和子群修改，切回恢复 |
| 面向对象 | 两组抽象接口及派生类体现多态，平台与群成员体现组合；菜单不直接修改数据容器 |
| 命名与注释 | 22 个类、7 个枚举均带 LJY 后缀；类独立文件、源码显式加入 CMake，保留现有简体中文普通 // 注释风格 |

微博默认 QQ 风格、好友确认后直接建立双向关系、群主踢管理员前须先降为普通成员、子群只允许一级，属于已批准的项目约定，不冒充课程原文逐字要求。课程原 doc 未修改。

实际实现见 [P2 实际类图](P2实际类图.md)。类数量从源码动态统计，未固定为 P1 的 12 个类。

## 6 当前限制与复现

当前为内存版本：默认启动重新加载虚构演示数据，`--empty` 启动空平台；退出丢弃操作结果。`--empty` 的新进程验证只证明当前不保存数据，不等于通过 P3 的重启恢复验收。尚无消息发送、SQLite 连接或数据库文件。

平时只需在项目根目录构建并运行业务回归：

```powershell
cmake --build --preset local-debug
ctest --preset local-debug
```

需要复现本次完整验收时执行一次：

```powershell
python tests/p2_acceptance.py
```

该入口先构建，随后依次执行现有测试，实时日志写入 `build/debug/p2_acceptance`；原有子群、原生控制台脚本仍保留各自输出目录。本次验收快照已另外复制到 `docs/P2验收记录`，后续构建不会覆盖报告证据。Python 脚本仅使用标准库，原生控制台检查需要 Windows。
