## 1 Qt 与工具

Qt 是 C++ 应用框架，本项目使用 Qt Widgets：QPushButton 表示按钮、QLineEdit 输入文字、QLabel 显示文字，布局类排列控件。Qt Creator 是可选编辑器，本机没有安装，继续使用 VS Code 与 CMake 即可。

| 工具 | 本机路径 | 用途 |
| --- | --- | --- |
| Qt 6.8.3 | `D:/Qt/6.8.3/mingw_64` | 头文件、库、DLL、moc 和 windeployqt |
| GUI MinGW 13.1 | `D:/Qt/Tools/mingw1310_64/bin` | 编译 GUI 及其核心库 |
| 原 MinGW 15.2 | `C:/mingw64/bin` | 编译终端 |
| CMake / Ninja | `C:/mingw64/bin` | 读取工程与调度构建 |

上述工具已安装，不需要重装。安装时用 aqtinstall 的独立环境下载 Qt 基础包与配套 MinGW，没有修改系统 PATH。`CMakeUserPresets.json` 中的 gui-debug 指定 GUI 工具路径；更换电脑时调整本机路径。

## 2 编译与启动

在项目根目录 PowerShell 执行：

```powershell
cmake --preset gui-debug
cmake --build --preset gui-debug --target jlu_im_gui
.\build\gui-debug\bin\jlu_im_gui.exe --demo
```

若找不到 cmake，使用 `& 'C:/mingw64/bin/cmake.exe'` 替换命令开头。重新构建前保存并关闭正在运行的 GUI，以免 exe 被占用。不要只移动 exe，运行需要同目录 DLL 和 `platforms/qwindows.dll`。

| 启动方式 | 行为 |
| --- | --- |
| 文件管理器打开 `build/gui-debug/bin/jlu_im_gui.exe` | 正常读写项目 `data/jlu_im.db` |
| `--demo` | 内存演示，关闭不保存 |
| `--empty` | 空平台内存练习，关闭不保存 |
| `--database .\build\gui-debug\练习.db` | 独立练习库，修改可保存；新库首次初始化演示数据 |
| `--help` | 查看参数与默认库位置 |

演示登录：QQ，账号 `10001`，密码 `DemoOnly123!`。正常模式的已有库恢复原数据；已有空库也不会重复初始化。

原终端仍使用 `cmake --build --preset local-debug` 和 `build/debug/bin/jlu_im.exe`。原 Ctrl+Shift+B 与 F5 仍指向终端；查看 Qt 头文件提示时，在 CMake Tools 选择 gui-debug 并配置。不要把“构建了终端”误当作“更新了 GUI”。

## 3 当前操作流程

卡片已统一为柔影与乳白微渐变材质：账号、好友、群管理、登录表单都有轻微悬浮层次。采用半透明底色模拟磨砂观感，正文没有模糊；窗口滚动和表单编辑方式保持原来行为。

图形端字体统一使用微软雅黑（Microsoft YaHei）：应用默认字体、主窗口、全局样式和登录页缩放样式保持一致。正文、表单标签、输入框和操作按钮用常规字重，标题与头像保留加粗；局部样式修改字号时仍沿用同一字体。


侧栏自上而下为“消息、群聊、我的账号、好友列表”，左图标、右文字；导航使用微软雅黑 16 像素常规字重，选中不加粗。“群聊”进入现有群管理，“好友列表”进入现有好友页；“消息”可在登录后打开准备中页面，实际收发与历史记录待 P5。登录和注销流程保持，当前登录后默认进入账号页，底部身份卡仍跳转账号页。

注册时输入两次密码；不一致或格式错误时不创建账号，保留其他资料供修正。成功后底部固定提示服务和号码，号码自动填入登录框，仍需密码登录。密码为 8—20 字节、ASCII 可见字符 33—126。

头像用昵称首字，按人员注册顺序在绿、蓝、珊瑚、紫、金、青六色间循环；同一人在不同服务和好友资料中颜色一致，改昵称和重启不改变颜色。点击“修改个人资料”后，头像下方出现六个沿浅弧排列的色块；点选立即预览，勾号和描边表示当前选择。点击“保存资料”一并提交，主动取消还原，切换导航保留草稿；资料校验失败保留草稿，不部分保存。仅支持六种预设，不支持自定义颜色。正常保存数据库后重启保留，账号页、好友资料和侧栏共用本人配色。

账号资料平时是文字，点击修改后才出现输入框；输入后点击保存资料或保存昵称提交。密码修改需原密码、新密码及确认密码，本人所有服务下次登录使用新密码。取消不提交，离开编辑状态清空密码。QQ 行单独展示绑定操作，会话状态始终保留；解绑只移除映射，不删账号、好友或群。

好友列表优先显示本人备注，其次昵称。点击修改备注后行内输入，再点保存备注；留空可清除，取消或换好友不提交。输入自己、已有好友或不存在的号码直接拒绝；有效目标确认后发送申请，尚未成为好友。删除仍需确认。

共同好友输入当前服务的对方号码；跨服务查询选择本人已开通的另一服务。推荐结果号码属于当前服务，未入选原因来自原业务；换条件会清空旧结果。查询结果下方始终有操作位置：共同好友已是好友，显示“已是好友”；选择“跨服务推荐”并查询后，选中结果点击“发送好友申请”，确认后等待对方处理。

“寻找同城好友”位于共同好友与推荐的查询方式中。选择后点击同名按钮，之后点击“换一批”：每次最多三人，最后不足三个照常显示，再点击从头开始。按当前服务、所在地文字完全一致匹配，排除本人、已有好友及双方待处理申请。换查询条件、切服务或数据刷新后从第一批开始。选中同城结果也能发送申请。

“好友申请”页签显示本人收到和发出的申请、对方号码及处理状态。接收方选中收到的申请后同意或拒绝；同意时才建立双向关系，发送方不能自行批准。拒绝后可重新发送，每对账号只保留最近一次申请。终端对应“8 好友管理 → 9 好友申请”，原搜索及推荐入口同样发送申请。正常模式下保存后可重启继续处理；演示模式下可注销后换账号在同一程序中审批。

左下角使用白色卡片，依次显示头像、居中加粗昵称、较小浅色账号，整块点击可进入我的账号；长昵称省略显示，悬停可看全文。配色略微增强侧栏与背景的绿色对比，应用使用绿色对话气泡图标。

群管理先从左侧列表选群，或在顶部输入当前服务群号查找。查找不存在的群立即清空旧目标，不允许继续选人；非成员只看到基本群信息及本人请求，不能查看成员表。待入群的申请与邀请也会出现在群列表中。

“群成员”表先显示号码、昵称和身份，点击成员后选择移除、设置管理员、取消管理员或转让群主，再确认操作。选中成员不显示权限错误，也不因权限置灰按钮；点击确认操作后才检查，例如不可移除自己、管理员不可移除群主、请先取消管理员身份，以底部浅红条反馈。改选目标或操作清理旧错误，自动刷新不会覆盖成功消息。请求审批、申请、退群和邀请同样在点击后检查；未选有效群时仍不能进入操作。退出群在群资料右上方，群主须先转让。

QQ 风格群由本人点击申请入群，再由群主或管理员在“申请与邀请”中选请求审批。微信风格群由成员输入被邀请人的号码发送邀请，再由对方登录、从待加入群入口接受或拒绝。提交前确认，取消不改变数据；请求状态更新为已同意、已拒绝或已失效。邀请输入和按钮保留，点击发送时检查权限。

演示时可以用 QQ 10001 查看群 1001，选择 10002 并点击移除操作，观察“先取消管理员身份”提示；微信 wx_20001 可在群 1002 邀请 wx_20004，再注销并登录 wx_20004 接受。演示密码均为 DemoOnly123!。QQ 申请可用 --demo 内注册的新账号查找 1001；注销后登录群主 10001 审批。

“子群与模式”页签先显示当前模式及直属子群。QQ 管理模式的父群群主点击创建子群后，页面展开群号、名称、群主及成员选择；群主自动勾选加入，不重复选择。确认提交或取消后收起。选择已有子群后点进入子群，可用返回父群回去；不能在子群内继续创建子群。父群移除成员会同步移除其子群资格。

切换管理模式只改变群规则，不改变所属服务。重复选择当前管理模式会显示红色错误条。切换确认框说明已有子群、成员和请求保留；取消不修改。已有子群继续使用自身模式，仍可查询和处理请求；父群为微信模式时不能创建新子群，切回 QQ 可继续创建。

成功或失败均在数据库路径上方固定显示，不随页面滚动。失败为浅红横条，普通消息为黑字无背景。已撤回上一轮固定 62 像素的放大调整，恢复原 42 像素最小高度和原样式。报错时仅警告条轻微左右震动约 0.32 秒、最大 5 像素，结束归位；普通和成功提示不动。长提示按需换行并可悬停查看全文。操作成功后立即自动写入 SQLite，顶部保存按钮已删除；输入框里未提交的草稿不等于已保存资料。注销前会重试失败的保存，失败则保留当前会话。保存失败可重试、取消关闭或明确放弃。

确认和保存失败选择使用窗口内遮罩卡片，按钮等宽同高，取消和确认不会一大一小。群成员操作使用具体标题（如“设置管理员？”），正文只显示昵称、号码、群号和必要影响；模式切换压缩为保留规则和权限变化。Esc 取消（纯提示为关闭），Tab 切换卡片按钮，Enter 执行当前按钮。资料、昵称、密码、备注仍保持原地编辑。侧栏加宽到 208 像素，导航使用微软雅黑常规字重 16 像素；登录页会随可用宽度放大文案、卡片、表单和间距，上限约 1.5 倍，避免大窗口里文字仍显得很小。

两个入口按“保存并关闭一个，再打开另一个”使用同一库，避免整体保存覆盖。独立练习使用 `--database`，只看界面可用 `--demo`。

## 4 代码怎样响应点击

终端等待 cin；GUI 进入 `QApplication::exec()` 事件循环等待鼠标和键盘。`connect` 将控件信号连接到成员函数，例如：

```cpp
connect(loginButton, &QPushButton::clicked,
        this, &LoginPageLJY::login);
```

它表示点击后执行 login，不代表另起线程。login 读取输入、转换字符串、调用 session.login，成功后发出 loggedIn，主窗口切换页面。错误通过 feedback 信号交给主窗口固定提示区。

```text
点击保存备注 → FriendsPageLJY::saveRemark()
 → session.updateFriendRemark(number, remark)
 → 原业务修改 Platform 内存 → changed → 主窗口刷新与提示

业务操作成功 / 失败后重试 → MainWindow 自动保存动作
 → main_gui 提供的回调 → SqliteStorageLJY::save(platform)
 → 成功反馈；失败保留内存供重试或选择退出
```

| 页面操作 | 业务入口 |
| --- | --- |
| 好友资料 | friends、friendAccount、friendPerson、friendRemark |
| 搜索添加 | friendCandidate → 内置确认 → sendFriendRequest |
| 删除与备注 | removeFriend、updateFriendRemark |
| 共同好友 | commonFriends、crossServiceCommonFriends |
| 跨服务推荐 | friendRecommendations → 选择确认 → sendFriendRequest |
| 同城推荐 | cityCandidates → 页面截取最多三人 → 选择确认 → sendFriendRequest |
| 好友申请 | friendRequests → 选择收到的申请 → handleFriendRequest，接收方同意后写入关系 |
| 群选择与资料 | groups、selectedGroup、group，未入群不调用成员查询 |
| 群成员操作 | checkGroupOperation → 选择确认 → kickGroupMember / setGroupAdministrator / transferGroupOwner / leaveGroup |
| 群申请与邀请 | applyToGroup / inviteToGroup；groupRequests 按当前群筛选；checkGroupRequest → 确认 → handleGroupRequest |
| 子群创建与查询 | group 提供父群成员 → 行内选择 → createSubgroup；subgroups 列出直属子群 |
| 群模式切换 | checkGroupOperation → 说明保留规则并确认 → switchGroupMode → 刷新 |
| 头像与资料 | updateProfile(name, birth, location, avatarColor)，全部校验通过后一起替换资料；终端不传颜色时保留原色 |
| 密码与解绑 | changePassword、unbindWeChatFromQQ，由会话取得本人身份 |

新增调用：sendFriendRequest → FriendManagerLJY::sendRequest → 平台申请容器；handleFriendRequest → handleRequest → 同意时创建 FriendRelationLJY 并更新状态。FriendRequestLJY 保存发送方、接收方和状态，friend_requests 表随原事务读写。旧库打开时 CREATE TABLE IF NOT EXISTS 自动补表，原有关系保留；不需要另装 SQLite，也没有新增编号计数器。头像选择新增 persons.avatar_color 字段，建库时提供默认值 -1，旧库通过检查字段后 ALTER TABLE 补建；-1 加载时使用原编号循环色，保存时写入 0—5。原直接添加接口仅保留用于内部演示数据与原业务用例，实际 GUI 和终端入口均走申请。

Q_OBJECT 支持自定义信号，AUTOMOC 调用 moc 生成配套代码；AUTORCC 编译资源，theme.qss 随程序分发，无须手动放到 exe 旁边。GUI 链接 `jlu_core` 与 Qt6::Widgets，核心不使用 Qt 类型。Qt 父对象管理子控件销毁，入口按生命周期持有平台、存储、会话和窗口。

推荐阅读顺序：`main_gui.cpp` → `LoginPageLJY.h/.cpp` → `MainWindowLJY.h/.cpp` → `AccountPageLJY.h/.cpp` → `FriendsPageLJY.h/.cpp` → `GroupsPageLJY.h/.cpp` → `InlineDialogLJY.h/.cpp` → `SidebarIconLJY.h` → `CardSurfaceLJY.h`、`UiFeedbackLJY.h`、`theme.qss` → `src/gui/CMakeLists.txt`。文件均位于 `src/gui`。审批业务接着读 `src/domain/FriendRequestLJY.h`、`src/services/FriendManagerLJY.h/.cpp`，最后看 `src/storage/SqliteStorageLJY.cpp` 和 `schema/create_tables.sql`。

## 6 发布版与重新打包

直接运行 `dist/JLU_InstantMessaging/jlu_im_gui.exe`；同目录 `jlu_im.exe` 为终端。分享使用 `dist/JLU_InstantMessaging_P4_Windows_x64.zip`，完整解压到可写目录后运行，无需安装 Qt、编译器、SQLite 服务或 MySQL。发布包没有复制项目的已有用户数据。

| 版本 | 默认数据库 | 工具链 |
| --- | --- | --- |
| 原终端 local-debug | 项目 data/jlu_im.db | 原 MinGW 15.2 |
| 图形 gui-debug | 项目 data/jlu_im.db | Qt 6.8.3 / MinGW 13.1 |
| 发布 gui-release，两个 exe | 实际 exe 目录下 data/jlu_im.db | 统一 MinGW 13.1 |

首次运行发布版自动创建库并加入演示数据。把整个发布文件夹移动后，数据库随文件夹移动；当前工作目录不会改变默认库位置。原有开发数据继续保留。如需沿用原库，可在关闭两个入口后复制原 data/jlu_im.db 到发布目录 data，先备份已有库；也可用 --database 指定原文件。Debug 与 Release 的默认库不同，不会自动同步。

在项目根目录 PowerShell 执行：

```powershell
.\scripts\package_p4.ps1
```

该脚本依次执行 `cmake --preset gui-release`、`cmake --build --preset gui-release`、`cmake --install` 和 `windeployqt --release`，复制匹配的 MinGW DLL、qt.conf、许可和说明，不删除已有 data；同时生成排除 data 和 .db 文件的便携压缩包。更换开发电脑时先调整 CMakeUserPresets.json 的工具路径，再按需传脚本参数 -QtRoot、-MinGWBin、-CMake；只运行发布包则无须这些开发工具。

`DefaultDatabasePathLJY.h` 使用 Windows GetModuleFileNameW 获得当前 exe 的完整 Unicode 路径，然后取父目录拼出 data/jlu_im.db；两个入口共用这个小函数，不需要为了移动文件夹重新编译。SQLite 仍由程序自动创建目录和表。

本机 Qt 不含翻译 catalogs，部署工具有非致命提示；界面文字由项目提供中文，部署已通过真实启动。发布时排除可选 DirectX 编译器和软件 OpenGL 组件，本项目使用 QWidget 控件，不依赖这些渲染功能。Qt DLL 和平台插件必须跟随程序，不能只复制一个 exe。
