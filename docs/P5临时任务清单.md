## 1 当前范围

三服务共用一套 Winsock2 TCP 文字私聊和 Qt 消息页。登录某服务后，只能与该服务的已有好友连接；两端必须选择相同服务且本地数据认可好友关系。没有连接真实 QQ、微信或微博官方网络。

- 一次连接一个好友；A 等待、B 主动连接，建立后双向收发，不增加云端服务器。
- UTF-8 中文、标点、换行及字体支持的表情；Enter 或按钮发送，Shift+Enter / Ctrl+Enter 换行。
- 每端用独立 SQLite 文件，自动保存本地聊天，默认最近 100 条，支持更早分页和离线查看。
- 断线后手动重连；注销、切服务、换好友及删除当前好友结束旧连接；查看其他页面仍接收。
- 私聊不包含图片、文件、语音视频、离线投递、已连通后的自动重连、已读或账号及好友资料同步。群消息广播与房间自动恢复已由第 8 节的独立群聊模块实现。
- 终端业务保留；日常聊天入口在 GUI，底层网络另有演示和测试程序。

## 4 当前技术约定

| 文件 / 类 | 职责 |
| --- | --- |
| TcpPeerLJY、TcpPeerChatLJY.cpp | Socket、后台收发、连接和资源生命周期 |
| ChatProtocolLJY | 帧编码/拆包，不操作页面或平台 |
| ChatIdentityLJY | 核对当前服务及好友，返回只含服务和账号的快照 |
| ChatMessageLJY | 编号、双方账号、正文、时间、状态、服务类型 |
| MessagesPageLJY | 控件、会话、事件处理、历史和待保存记录 |
| ChatHistoryLJY | SQLite 独立消息存储及旧 QQ 记录迁移 |
| ChatBubbleLJY | 头像旁带尖角气泡的绘制 |

协议 2 的八行头：版本、类型、服务（0 QQ / 1 微信 / 2 微博）、发送端连接标识、消息编号、发送账号、接收账号、Unix 毫秒；之后是原样正文。外层四字节大端长度不含自身。双方需更新到协议 2，旧版本明确拒绝，不自动降级。

网络工作线程不访问 QWidget、SessionManager、Platform 或 SQLite。GUI 用 50 毫秒定时器取事件；Socket 每轮最多等待 50 毫秒。主动连接 10 秒、握手 5 秒、发送及 ACK 总等待 10 秒超时；监听可一直等待。无心跳，空闲时静默断网不保证立即识别。

消息表实际字段：id、service、owner_account、peer_account、message_key、direction、body、message_time、local_time、delivery_state。唯一约束为 service + owner_account + message_key，索引为 service + owner_account + peer_account + id。原 QQ 表整表复制到新结构时 service 填 0，原行号及内容保留，事务失败回滚。

聊天不放进 Platform，也不对会被原保存流程替换的账号表建外键。账号/好友/群按原方式保存；聊天逐条保存。每端只管理自己的数据库，双方没有共享库或分布式账号同步。
