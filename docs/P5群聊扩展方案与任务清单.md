# P5 群聊扩展方案与任务清单

日期：2026-10-14。用户已批准本方案全部批次实施。这是 P5 的群聊扩展，不启动 P6 课程报告阶段。

## 一、目标与使用流程

消息页增加“好友 / 群聊”页签。选择本人参加的群即自动找房间并加入，输入框可立即编辑，建立连接后 Enter 直接发送；Shift+Enter、Ctrl+Enter 换行。无需每次点击开始、监听或连接。首位进入者（包括普通成员）自动开启房间并分配端口；后续成员连接同一房间。刚进入时有短暂发现与握手，未就绪的文字留在输入框，不伪称已经发送。

群管理页保留原功能，另提供进入所选群聊天的入口。聊天主持端只是临时的转发电脑，不改变群主、管理员或成员身份。每个窗口同时参加一个实时群房间，切到账号/好友/群管理页面仍保持群连接；选择另一个群、切服务、注销或关闭时离开原群房间。私聊与群聊使用各自的连接，可以同时保持。

## 二、自动房间与端口

### 本机演示

同一服务同一群号得到相同的默认 TCP 端口：32000 + (服务编号 × 997 + 群号) % 20000。首次进入时尝试监听该端口，绑定成功者成为主持端，并让自己的客户端加入；绑定失败者连接这个本机端口上的现有房间。操作系统的独占端口保证同一端口只有一个等待方。端口与其他程序冲突或不同群号映射碰撞时明确报错，可在内置设置修改房间端口，两端配置应一致。

### 两台或多台电脑

同一可互通局域网内使用 UDP 组播发现（239.255.42.99:45045），发现报文只包含协议、服务、群号、房间标识和 TCP 端口，不包含聊天正文。TCP 才承担成员握手和消息收发。先短暂寻找现有房间，无房间则自动监听；首选默认端口，局域网端口占用时允许系统分配空闲端口并公告。多个窗口同时建立候选房间时，通过固定比较房间随机标识收敛到一个主持端；连接可能短暂切换，旧消息不自动重发。

局域网禁止组播时，可在更多设置指定现有房间的 IP 和端口。指定 IP 模式只自动连接该地址，不在连接失败时另建孤立房间。主持端显示实际端口，便于复制。设置保存在该数据库旁的群连接 INI 中，不改账号数据。公网/NAT 穿透、云服务器、跨网段发现不在本批范围。

### 主持端退出

其他成员检测断开后自动重新发现并竞选，重新进入房间。历史仍保存在各端；发送中但未确认的消息标记结果未知，保留文字供用户处理，不自动补发。房间唯一性依赖同一网络中发现报文可达；网络分区时不能承诺全网只有一个房间。

## 三、协议与成员权限

使用独立的群协议，不修改私聊协议 2。TCP 外层使用四字节长度、内层使用 UTF-8 JSON；消息上限 16 KiB，帧上限 64 KiB。帧类型包括入房、接受、拒绝、发送正文、广播正文和在线名单；离房直接关闭 Socket。

群会话以服务和群号隔离，子群使用自己的独立群号。主持端用本地已有群成员清单检查入房账号；同账号重复连接拒绝。收到正文时依据已握手 Socket 的账号确定发送者，不能信任正文中自称的账号。主持端分配房间编号及递增序号，向所有在线成员（包括发送者）回传，发送者收到回传后显示“房间已接收”，不宣称所有人已读。

各端已有独立账号库，不新增账号同步。主持端的本地成员清单决定房间入场资格；主持端执行成员移除后断开该账号，新增成员可随后进入。其他电脑的群资料变更不会自动同步到主持端；演示前应使用一致群资料。群模式切换保留子群，其聊天按原所属服务和群号保持独立。微博是否显示群由现有业务决定，不创造业务层不存在的群。

这是课堂可信局域网模拟，握手验证群成员账号，不新增联网密码认证和端到端加密，不作为公网安全聊天服务。

## 四、界面与历史

消息页“群聊”列表显示群名、群号；右侧显示群名、在线人数、主持端和端口。消息显示发送人昵称、首字头像和本地六色，自己靠右、其他人靠左；正文支持选择复制，超过六行可展开/收起。底部状态沿用现有固定提示区，普通发现等待不显示红色，确实失败才报错。

新增 group_chat_messages 独立表，以服务、本人账号、群号、消息编号隔离，保存发送者、发送时昵称、头像色、正文、时间，只存房间已回传的记录。未确认文字保存在运行中的输入草稿，不作为已发送历史落库。最近 100 条和加载更早消息，离线可看本地历史。各端仅保存自己在线收到的消息，不做离线投递或自动补齐。写入失败保留内存和待保存队列，保存/退出提供重试、取消和明确放弃。

## 五、代码组织

- GroupChatProtocolLJY：长度分帧和 JSON 解析。
- GroupChatHostLJY：接受多连接、成员检查、在线名单、正文转发。
- GroupChatClientLJY：自动发现、开房/加入、主持端交接、发送与接收。
- GroupChatMessageLJY / GroupChatHistoryLJY：消息值和独立 SQLite 历史。
- GroupMessagesPageLJY：群列表、设置、气泡、发送、保存与页面联动。

群网络采用 Qt Network 的异步 Socket 与事件循环，不在 GUI 线程进行阻塞 accept/recv，也不建立线程池；已有私聊继续用原 Winsock 后台线程。复用已有字体、卡片、头像和内置确认样式。关键声明使用简体中文 // 注释和 LJY 后缀，保持课设可读性。
