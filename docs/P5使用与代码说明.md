# P5 使用与代码说明

2026-10-27 补充：[本地多窗口同步修复与验收](P6本地多窗口好友同步修复与验收.md)。`id_state.revision` 记录业务版本；GUI 每 500 毫秒重读其他窗口已提交的业务变化，保存时拒绝旧副本覆盖。业务表仍为十张，聊天写入不触发业务刷新；仅同一数据库路径参与同步。

更新：2026-10-21（P6 9A）。当前版本面向同一 Windows 电脑上的多个独立窗口，移除了双机/IP 设置、局域网发现及远端群服务入口。仍通过真实 TCP Socket 收发消息，Qt 图形界面、原终端业务、SQLite 和群离线补齐保留。

## 日常启动与保存

解压完整目录后运行 `jlu_im_gui.exe`，保留同目录 DLL、插件和 `jlu_group_server.exe`；不用安装 Qt、编译器、SQLite 服务或 MySQL。`jlu_im.exe` 保留终端业务入口。当前便携包仍使用 P5 文件名，P4 包仅是历史版本。

便携版默认库为 exe 旁的 `data/jlu_im.db`，新库首次初始化演示账号，已有库恢复原数据。图形端账号、好友、群操作提交成功后自动保存；输入框中尚未提交的内容只是草稿。底部固定显示保存状态，失败可重试。终端保留原来的保存菜单；聊天记录逐条保存。

`--database "路径"` 指定其他库，相对路径按当前终端目录解释；`--demo` / `--empty` 是内存练习，关闭后不保留客户端数据。GUI 与终端使用同一库时先关闭一个再启动另一个。

## 本机双窗口私聊

在便携目录的 PowerShell 中运行：

```powershell
.\jlu_im_gui.exe --database '.\demo-A.db'
.\jlu_im_gui.exe --database '.\demo-B.db'
```

每个窗口使用独立库；新文件初始化同样的演示基线，不覆盖已有文件。双方选择同一服务，演示密码均为 `DemoOnly123!`：

| 服务 | A 的号码 | B 的号码 |
| --- | --- | --- |
| QQ | 10001 | 10002 |
| 微信 | wx_20001 | wx_20003 |
| 微博 | 10001 | 10005 |

进入“消息 → 私聊”，选择彼此，双方点击“开始聊天”。地址固定为 `127.0.0.1`，默认 TCP 端口 27015。数字账号较小者等待、较大者连接；含字母的账号按固定字符串顺序比较，自动分工，不用手动选择监听或连接。

“更多设置”只保留本机端口、恢复默认、保存/取消和断开连接。两端端口需相同；在线改端口下次连接生效。旧版双机模式与 IP 配置不再使用，加载/保存时清理废弃键，保留已存端口。

Enter 发送，Shift+Enter / Ctrl+Enter 换行。长消息先显示 6 行，可展开全文。未连接时草稿保留，不会发送到另一段会话。

一次只实际连接一位好友。浏览其他好友保留原连接，原好友消息继续接收；返回可继续发送。点击新好友的“开始聊天”才替换连接；主动断开、切服务、注销、删除已连接好友或退出会结束连接。

主动方先开始遇到连接拒绝或连通前超时，每 2.5 秒重试，累计最多 60 秒，可以取消；等待方持续等待。已连接后断线需手动重连，不自动重发正文。“对端已接收”表示对端程序收到，不等于用户已读或成功写库。未确认消息显示结果未知时，由本人判断是否重发。

## 本机多人群聊

实时入口为“消息 → 群聊”，群管理保留成员、申请、邀请及权限操作。正常数据库模式自动连接或启动本机独立群服务；本人其他群继续后台接收，前台只展示一个群。群主无需先上线，任一成员均可触发启动。

使用三个独立数据库启动三个窗口（例如 group-A.db、group-B.db、group-C.db），选择同一服务及 1001 群：

| 服务 | A | B | C | 1001 群默认 TCP 端口 |
| --- | --- | --- | --- | --- |
| QQ | 10001 | 10002 | 10003 | 33001 |
| 微信 | wx_20001 | wx_20002 | wx_20003 | 33998 |
| 微博 | 10001 | 10004 | 10005 | 34995 |

状态显示“群历史已同步”后即可发送。群设置只保留本机地址说明和房间端口；端口默认根据服务与群号计算，同群窗口应保持一致。没有 UDP 发现端口，不需要配置网卡或远端 IP。

独立群服务先将消息写入日志，再确认和广播；客户端重新连接时分批补齐并去重保存。关闭一个窗口不会关闭仍有其他成员使用的群服务；无人连接 60 秒后服务退出，下次自动启动并恢复。原本没有任何副本的旧消息无法凭空恢复。

`--demo` / `--empty` 不落库，使用仅限本机的内存房间；关闭主持窗口后其余窗口可重新开房继续即时演示，但不能用于离线恢复验收。它与已删除的局域网临时发现模式不同。

完整成员名单可显示在线和离线状态；同机成员变更按差异更新共享名单，旧窗口刷新不会把已移除成员重新加回。各客户端业务数据库仍独立，不是集中式账号管理系统。子群独立聊天，主群切微信模式保留既有子群和历史。

## 历史、未读与列表

私聊和群聊按服务及本人账号隔离，初次显示最近 100 条，“加载更早消息”向前翻页。群历史需要先连接持久服务补齐；未同步时只说明本地记录已读完，不冒称已到服务端历史起点。

好友和群列表支持搜索、最近摘要和时间排序。翻阅旧消息不自动滚到底部；红色数字显示未读，输入框上方浅色横条点击后定位最早未读，必要时补读旧页。读到末尾再清除未读。

写库失败会保留待保存信息并提供重试；不要将未保存提示当作已经成功落库。私聊不提供离线投递，当前不支持图片、文件、语音视频和对端已读回执。

## 数据位置与备份

| 数据 | 位置/说明 |
| --- | --- |
| 便携客户端业务与聊天 | exe 旁 data/jlu_im.db |
| Debug 默认客户端库 | 项目根目录 data/jlu_im.db |
| Release 构建目录的库 | build/gui-release/bin/data/jlu_im.db，与 dist 的库不同 |
| 本机群服务日志及名单 | %LOCALAPPDATA%/JLU_InstantMessaging/group-server |
| 私聊设置、群设置、私聊未读 | 数据库旁 .connection.ini、.group.connection.ini、.unread.ini |

日常建议固定使用 dist/JLU_InstantMessaging 的程序，并查看界面底部实际数据库路径。换 exe 目录可能打开另一份库，不代表旧记录删除，也不会自动合并。旧版本自定义的端口继续使用，远端 IP 不会使新版连接外部电脑。

备份前确认保存成功，关闭相关客户端和群服务，再复制客户端库/配置以及群服务日志目录。只复制客户端 data 不包含服务端日志；覆盖另一份数据库也不等于合并聊天。便携包不包含用户数据库。

Qt 动态链接、SQLite 与运行库许可在 licenses 中；使用 Windows 自带微软雅黑，不分发字体。程序只模拟项目内 QQ、微信、微博账号，不连接官方产品网络。实体双机未实测，当前已取消其产品入口；本机演示无需云服务器或防火墙放行。

## 开发与代码阅读

在项目根目录配置 `cmake --preset gui-debug`，再构建 `cmake --build --preset gui-debug`；终端用 `local-debug` 预设。`scripts/package_p5.ps1` 负责 Release 构建、部署和打包，实际工具路径在 `CMakeUserPresets.json`。

1. [main_gui.cpp](../src/gui/main_gui.cpp) 与 [DefaultDatabasePathLJY.h](../src/storage/DefaultDatabasePathLJY.h)：启动参数、默认库和群服务目录。
2. [MainWindowLJY.cpp](../src/gui/MainWindowLJY.cpp)：导航、业务变更自动保存、未保存状态和关闭流程。
3. [MessagesPageLJY.cpp](../src/gui/MessagesPageLJY.cpp)：区分浏览对象与连接对象，beginConnection/sendText/pollEvents，以及历史与未读展示。
4. 私聊身份、分帧、后台收发和逐条存储：按 [第五批说明](P5第五批说明与验收.md) 的调用顺序阅读。
5. [群离线同步说明](P5群离线同步方案与验收.md)：独立服务、先写库再广播、离线补齐和分页。
6. [交互改进说明](交互改进_1-11_说明与验收.md)：名单差异合并、后台多群接收、红色未读和最早未读定位。

历史阶段测试见 [P5 总体验收](P5第六批与阶段总体验收.md)；后续课程核对与交付安排见 [P6 临时任务清单](P6临时任务清单.md)。只需沿主线理解调用关系，不必逐行阅读所有测试和样式。

自动连接的旧版验收记录保留于 [2026-10-14 记录目录](P5验收记录/自动连接_2026-10-14)，其中双机/IP 用例仅代表当时版本。9A 的实际清理与检查见 [9A 说明](P6_9A本机通信清理与验收.md)。
