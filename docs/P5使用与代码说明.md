# P5 使用与代码说明

Windows x64，Qt 6.8.3 / MinGW 13.1 Release。解压整个目录后运行 jlu_im_gui.exe；不用安装 Qt、编译器、SQLite 服务或 MySQL。jlu_im.exe 保留终端业务入口。

## 日常使用

首次正常启动在 exe 旁的 data/jlu_im.db 初始化演示数据，之后恢复原库。账号、好友、群的修改通过“保存数据”或正常退出提交。聊天记录逐条自动保存。备份时保存并关闭程序，再复制 data 文件夹。

`--database "路径"` 选择其他数据库，`--demo` / `--empty` 是关闭后不保留的内存练习。原终端与 GUI 使用同一库时，先保存并关闭一个，再打开另一个。

QQ、微信、微博的“消息”页和好友资料“发消息”均已可用。只能与当前同一服务的已有好友文字私聊；没有接入腾讯/新浪真实账号。双方程序必须更新到本版协议 2。旧 P5 QQ 历史首次打开聊天时自动迁移并保留；原业务表不变。

## 本机两个窗口对话

在解压目录打开 PowerShell，使用两个不同数据库：

```powershell
.\jlu_im_gui.exe --database '.\demo-A.db'
.\jlu_im_gui.exe --database '.\demo-B.db'
```

新文件会初始化相同演示基线；不会覆盖已经存在的文件。双方选同一个服务，然后按下表登录（密码均为 DemoOnly123!）：

| 服务 | A | B | 预置好友 |
| --- | --- | --- | --- |
| QQ | 10001 | 10002 | 演示 A、B |
| 微信 | wx_20001 | wx_20003 | 演示 A、D |
| 微博 | 10001 | 10005 | 演示 A、E |

在“消息”中各选对方，选择“本机演示”，两个窗口都点击“开始聊天”。默认地址 127.0.0.1、端口 27015；如需改端口，在“更多设置”中保存，两端保持一致。程序自动决定等待方和主动方，点击顺序不限。Enter 或发送按钮发送；Shift+Enter、Ctrl+Enter 换行。

同一时刻一个窗口只连接一位好友。切好友、切服务、注销都会停止原连接；切到资料等其他页面仍能接收。手动断开后可以点击“重新连接”，已有历史保留。

## 历史与失败提示

历史按“服务＋本人账号＋对端账号”隔离；同号码的 QQ 和微博不会混在一起。默认最近 100 条，点击“加载更早消息”向前翻阅。关闭后使用原数据库重开、登录、选好友，无需连线就能看历史；不会恢复旧连接或自动重发。

“对端已接收”只表示对方程序收到完整消息，不代表用户已读或已写库。未等到确认就断线时可显示“结果未知”。写库失败仍显示收到的消息，并保留待保存数量、重试入口。关闭时可重试、取消、明确放弃；取消关闭后连接已停止，可手动重连。

主动方先开始时，连接拒绝或连通前超时会间隔 2.5 秒重试，总等待上限 60 秒，期间可取消；等待方可持续等待。端口占用或身份不匹配直接显示红色错误。已连接后断线需点击“重新连接”，不会自动重发消息。底层单次连接最多 10 秒、握手 5 秒、发送或 ACK 总等待 10 秒；没有后台心跳，不承诺空闲断网立即识别。

## 两台电脑

两台电脑各放完整发布目录，数据库各用自己的副本。演示可在两端从新库初始化；已有自定义好友数据先保存为共同基线，再分别复制到两端。联网不会同步账号、密码、好友或群。

双方连接同一可互通局域网，选择“两台电脑”。“更多设置”显示本人的自动角色：数字账号较小者等待；含字母账号按字符串顺序决定，双方结果一致。等待方通过网卡下拉框选择并复制本机 IPv4，主动方把这个地址填入“等待方 IP”并保存，两端端口一致。等待方实际监听 0.0.0.0，本机网卡下拉框用于选择提供给对方的地址。双方点击“开始聊天”即可，两台电脑不能使用 127.0.0.1 互连。若 Windows 询问防火墙访问，由使用者按自己的网络环境允许应用；不要关闭整个防火墙。

本项目自动验收覆盖本机独立进程，当前未实测两台实体电脑。跨不同网络/NAT、公网转发、云服务器部署未包含在 P5。

“群聊”侧栏保留群管理；实时群消息入口在“消息 → 群聊”，也可从群管理跳转。群房间支持自动加入和断线恢复；暂不支持图片、文件、语音、视频、离线投递或已读。

第三方许可及组件清单在 licenses 中。Qt 动态链接、未修改 Qt；SQLite 源码在课程项目 third_party/sqlite；MinGW 运行库许可随包提供。使用 Windows 自带微软雅黑，不分发字体文件。


## 开发与代码阅读

从项目根目录构建 GUI：`cmake --preset gui-debug`，再执行 `cmake --build --preset gui-debug`。原终端使用 local-debug 预设；`scripts/package_p5.ps1` 构建并部署 Release、生成 P5 zip。具体工具路径在 CMakeUserPresets.json 中。

优先阅读：ChatMessageLJY.h → ChatIdentityLJY.cpp → ChatProtocolLJY.cpp → TcpPeerChatLJY.cpp → MessagesPageLJY 的 sendText/pollEvents → ChatHistoryLJY 的 save/load → MainWindowLJY 的关闭流程。暂时不必逐行阅读所有测试和 Qt 样式。

函数调用与迁移细节见 [第五批说明](P5第五批说明与验收.md)，最终证据见 [第六批与阶段总体验收](P5第六批与阶段总体验收.md)。课程项目保持简体中文 // 注释和 LJY 后缀，普通界面交互复用原业务逻辑。

## 消息和好友界面补充（2026-10-14）

侧栏顺序为“消息、群聊、好友列表、我的账号”。长消息默认显示前 6 行，点击“展开全文”或“收起”切换，完整记录不受影响。消息页好友左侧显示头像，右侧三个圆点可直接打开该好友资料，不改变当前聊天连接。好友资料底部三个操作按钮以紧凑同排样式显示。


## 更多设置与草稿

设置以独立 INI 文件保存，正常模式位于数据库路径后追加 `.connection.ini` 的文件，本机和两机的端口分别保存，两机同时保存等待方 IP。内存练习模式使用当前应用配置目录中的 connection.ini，不写聊天数据库。在线修改并保存 IP 或端口，下次连接生效，不打断本次聊天；恢复默认只修改表单，仍需保存，取消会还原表单。

展开设置时临时使用聊天内容区，保存或取消后返回；后台继续收发。未连接时也可编辑草稿，Enter 会提示先连接并保留文字。不要在正式数据库上同时运行两个编辑窗口；本机双窗口仍各用独立数据库。


## 多人群聊：选择群即可加入

侧栏“群聊”仍负责群管理，选中自己的群后点击“进入群聊”；也可进入“消息 → 群聊”页签，直接点左侧群名。首位进入者自动开房并使用该群端口，其他人自动加入，无需点击开始、监听或连接。普通成员也可以首先进入。等待“已加入”后按 Enter 发送；Shift+Enter、Ctrl+Enter 换行。连接建立前可编辑文字，发送失败不会丢失输入。

本机演示可同时开三个窗口，各用独立数据库：

```powershell
.\jlu_im_gui.exe --database '.\group-A.db'
.\jlu_im_gui.exe --database '.\group-B.db'
.\jlu_im_gui.exe --database '.\group-C.db'
```

新库的演示密码均为 `DemoOnly123!`，三端选择相同服务、群 1001：

| 服务 | A | B | C | 1001 群默认端口 |
| --- | --- | --- | --- | --- |
| QQ | 10001 | 10002 | 10003 | 33001 |
| 微信 | wx_20001 | wx_20002 | wx_20003 | 33998 |
| 微博 | 10001 | 10004 | 10005 | 34995 |

可以故意让 C 先进入，再让 A、B 加入，验证开房不依赖群主。关闭主持窗口，其他成员会自动重建或加入新房间；不自动重发未确认正文。不要让多个窗口同时编辑一个数据库。

两台或多台电脑：各自拥有一致群成员资料，进入同一群，在“更多设置”将连接方式改为“局域网自动发现”，指定 IP 留空，保存后自动发现现有房间；找不到时自行开房。配置会记忆，下次点群即可加入。局域网组播可达时无需手填 IP；自动发现不通时，让一人保持自动模式开房，其余人填该主持电脑的实际局域网 IPv4 和页面显示的端口。网卡下拉框可复制本机 IPv4，请选择实际互通网卡而非虚拟网卡。指定 IP 模式只连接这个地址，不另行竞选主持端。跨互联网或 NAT 不包含在此功能内。

群设置存入数据库旁的 `.group.connection.ini`，按服务和群号分别记忆；保存设置后立即重新加入该群。主持端用本地群成员名单检查入场；在主持端移除成员会断开该账号。其他电脑的群资料改动不会自动同步，应先统一群成员资料。子群按自身群号独立聊天，切主群管理模式不删除子群或聊天记录。

每端自动保存自己在线收到的群消息到 `group_chat_messages`，按服务、本人账号和群号隔离；最近 100 条、加载更早、重启恢复均可用。房间回传后才显示“房间已接收”，不代表所有成员已读。断线或确认超时的未确认文字放回输入框，由本人判断是否重发；无离线补投、草稿重启恢复或全员历史同步。写库失败保留内存记录，保存或退出可重试。每个窗口同时参与一个实时群，切其他功能页保持连接，换群、换服务、注销或关闭会离开；私聊连接可同时保持。

群聊代码阅读及原理详见 [群聊实现说明与验收](P5群聊实现说明与验收.md)。群网络采用 Qt Network 事件循环；上文后台线程、私聊 ACK 与手动重连的描述仅对应私聊。

群历史分页：默认显示最近 100 条。点击“加载更早消息”会显示新加载的一批旧消息，并提示加载条数；没有更早记录时按钮显示“已到最早消息”，空历史显示“暂无群聊天记录”。此功能读取当前数据库中已经保存的记录，不从其他成员电脑补齐离线消息。
