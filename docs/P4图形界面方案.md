## 1 范围与技术选择

采用 C++17、Qt 6 Widgets 和 CMake，提供独立 `jlu_im_gui.exe`。原终端 `jlu_im.exe` 保留，两个入口共用业务核心与 SQLite 数据格式。P4 完成账号、好友、群管理及保存关闭的窗口操作；TCP 私聊与群聊已在 P5 实现，最终课程交付属于 P6。

本机使用 Qt 6.8.3 与配套 MinGW 13.1；原终端 Debug 继续使用 MinGW 15.2。便携 Release 内的两个入口统一使用 MinGW 13.1，避免同目录运行库冲突。`gui-debug` 使用独立构建目录并重新编译核心与 SQLite，不链接旧工具链的静态库。Qt 依赖限定在 GUI 目标，根 `JLU_BUILD_GUI` 默认 OFF，原 `local-debug` 可独立构建。

ElaWidgetTools 兼容检查已经结束：固定提交 `aae58f5d0d98e05eabe10c263aa7da5f2491d702` 的上游配置拒绝当前 Qt 6.8.3，未进入源码编译。采用原 Qt Widgets 借鉴视觉风格，正式工程不接入 Ela，不更换工具链。该结论仅针对所检查版本及配置，见 [兼容检查日志](P4验收记录/Ela兼容检查.log)。

## 2 结构与调用

```text
终端入口 main.cpp → ConsoleAppLJY ─┐
                                 ├→ SessionManagerLJY → 原业务类 → PlatformLJY
图形入口 main_gui.cpp → Qt 页面 ──┘
两个入口各自创建 SqliteStorageLJY，负责启动读取及保存平台数据。
```

两个进程各有一份内存，不共享运行状态。GUI 只在边界转换 QString 与 UTF-8 std::string；不让业务类依赖 Qt。页面保存账号或群号，操作时重新查询对象，不长期持有可能失效的实体指针。

| 文件 | 职责与状态 |
| --- | --- |
| `src/gui/main_gui.cpp` | 已实现：参数、SQLite、会话、窗口、事件循环 |
| `MainWindowLJY.h/.cpp` | 已实现：导航、服务切换、保存、关闭、固定提示 |
| `LoginPageLJY.h/.cpp` | 已实现：注册、确认密码、号码提示与登录 |
| `AccountPageLJY.h/.cpp` | 已实现：资料、昵称、密码、服务和绑定 |
| `FriendsPageLJY.h/.cpp` | 已实现：好友资料、申请审批、删除备注、共同好友、跨服务和同城推荐 |
| `GroupsPageLJY.h/.cpp` | 已实现：群资料、成员、申请邀请、子群与模式切换 |

除入口外，以上窗口文件均在 `src/gui`。继续采用简体中文 `//` 关键注释，头像统一调用 `AvatarLJY.h` 中的小函数，注册时按人员编号循环分配六色；修改资料时可在六种预设间选择，Person.avatarColor 和 persons.avatar_color 保存选择，旧库自动补字段。不为每个按钮新建类，不增加事件总线、仓储层或通用主题框架。布局使用 Qt 布局管理器。

原终端界面最大程度保留。GUI 优先复用业务接口；已为密码修改和解绑补充业务接口；本次好友审批增加 FriendRequestLJY、业务接口及 friend_requests 表，终端增加“9 好友申请”，搜索和推荐均改为申请制。后续确需补充业务接口时说明实际影响并验证，不能把“核心从未改变”当作现状。

## 3 统一外观与交互

图形端字体统一使用微软雅黑（Microsoft YaHei）：应用默认字体、主窗口、全局样式和登录页缩放样式保持一致。正文、表单标签、输入框和操作按钮用常规字重，标题与头像保留加粗；局部样式修改字号时仍沿用同一字体。


背景采用 #f1f6f3，侧栏采用 #dceae2，略微增加层次对比；卡片采用高不透明度乳白到浅绿的微渐变、14 像素圆角、细边框及白色上缘高光，配合灰绿色柔影；绿色强调色保持。应用图标为绿色对话气泡，Qt 资源用于窗口，ico/rc 用于 Windows exe。侧栏宽 208 像素，依次为“消息、群管理、好友列表、我的账号”，图标在左、文字在右。四种透明图标由 SidebarIconLJY.h 按参考造型绘制，支持多尺寸缩放；导航固定使用微软雅黑（Microsoft YaHei）16 像素常规字重，选中仅改变底色与左侧标记。登录文案、表单与间距随可用宽度放大，上限约 1.5 倍，卡片居中且限宽。窗口默认 1200×820、最小 900×600；内容可滚动，操作提示和数据库路径留在滚动区之外。

| 区域 | 当前规则 |
| --- | --- |
| 登录 / 注册 | 扁平页签；密码隐藏、再次确认；失败保留其他资料；成功号码显示在底部并填入登录框 |
| 消息 | 私聊 / 群聊页签；真实 TCP、头像气泡和 SQLite 历史已由 P5 接入，连接设置为内置表单 |
| 我的账号 | 基本信息、安全设置、账号关联三块卡片；头像取昵称首个可见字符，注册时循环六色，修改资料展开头像下方六色浅弧选择器；选中预览，保存提交、取消还原 |
| 资料 / 昵称 / 密码 | 点击后原地展开输入框，保存或取消后收起；资料和昵称编辑时隐藏另一入口；修改按钮为珊瑚红 |
| 账号关联 | 服务、号码、昵称、申请日期、会话状态始终展示；只有 QQ 行有独立绑定操作列；已绑定按钮置灰；解绑行内确认 |
| 我的好友 | 添加、列表、资料三块卡片；昵称首字头像；备注行内编辑时隐藏修改和删除按钮 |
| 共同好友与推荐 | 查询条件、结果、未入选说明分区；结果下方始终保留操作位置；共同好友显示“已是好友”，跨服务和同城推荐选中后可发送好友申请；换条件清空旧结果 |

| 同城推荐 | 按当前服务和所在地文字完全相同查询，排除本人、好友及待处理申请；每批最多三人，尾批不足三个照常显示，取尽后循环 |
| 左下角身份 | 白色卡片；头像、居中加粗昵称、小号浅色账号分三行；整块可点击进入我的账号 |
| 群管理入口 | 侧栏名称为“群管理”；先选群，再从当前群资料旁“进入群聊”；实时聊天在消息页 |
| 群管理 | 群列表含已加入群及本人待入群记录；先选有效群，再选择成员或请求；选中目标不报错，权限不锁定按钮，点击操作后才在底部红条显示失败原因 |
| 操作反馈 | 数据库路径上方固定显示；失败为浅红横条，普通或成功消息为黑字无背景；恢复原 42 像素最小高度，长文字按需换行；报错时条形左右轻晃约 320 毫秒、最大 5 像素，结束归位，成功消息不动；长文字换行，悬停可读完整内容 |

绑定、权限和资格检查使用原业务规则；当前服务不可重复切换。重复选择当前群管理模式也使用红色错误条。所有已提交修改先进入内存，随后立即自动写入 SQLite；顶部保存按钮已删除，失败时在底部重试。好友申请每对账号只保存最近一次状态，使用现有保存事务；打开旧库自动补表，已有好友不需要重新申请。

## 4 群界面规则

第四、第五批已完成群选择、成员、请求、子群与模式，沿用上述卡片风格。下列规则及群修改后的保存关闭失败联动均已落实。群列表同时展示本人待处理的申请或邀请，非成员可选群处理本人请求，但不能查看成员资料。

1. 先选择有效群，再展示资料、成员、申请邀请及相关操作；可通过群号查询尚未加入的群。不存在的群立即提示，不继续要求选择成员。
2. 操作前展示成员号码、昵称和身份。本人不可被自己移除；群主移除管理员前须先取消其管理员身份；管理员不能移除群主或管理员，失败原因须明确。
3. 申请、邀请、审批和接受按当前群及本人权限展示。QQ群使用申请审批，微信群使用成员邀请与被邀请人接受；实际规则调用原群策略。
4. 退群、踢人、管理员任免、群主转让沿用原规则；修改前确认，取消不改变数据。
5. “子群与模式”页签只建立一级子群，群主及初始成员从父群成员中选择，群主自动加入；表单行内展开。父群成员退出或被移除时同步更新子群资格。主群切换只改变自身模式，已有子群、成员及请求保留，子群继续使用自身规则；微信模式禁止新建子群，切回 QQ 可继续创建。
6. 仅未选有效群时关闭操作区；点击操作后使用 `checkGroupOperation` 等原接口，合法操作确认后提交；不在界面重复编写权限体系。

## 5 保存、共存与验收

无参数时，Debug 读取项目 data/jlu_im.db，便携 Release 读取 exe 同目录 data/jlu_im.db；`--database` 指定练习库；`--demo` 和 `--empty` 只使用内存。注销清理会话，不等于保存退出。关闭保存失败时现有程序已提供重试、取消关闭和明确放弃；第五批已用隔离 SQLite 库的真实写入失败验证群修改后的三种选择，复用已有关闭逻辑。

两个入口使用同一库时，先保存并关闭一个，再打开另一个。当前是整体平台保存，多进程同时编辑可能互相覆盖，不在课设范围内扩展同步系统。

按改动范围验证：布局改动运行受影响 GUI 用例，核心改动再运行相关业务回归；不用每次改样式都重跑全部键盘和核心测试。第六批已完成综合回归、双入口读写、终端保留核对和 Release 部署。最新 25 + 13 项 CTest 全部通过，历史绑定测试限制未再出现；证据见验收第 13 节。

## 6 Release 交付

`gui-release` 继承 GUI 工具链，使用独立 build/gui-release，关闭测试目标并启用 JLU_PORTABLE_DATA。`DefaultDatabasePathLJY.h` 根据实际 exe 路径定位 data；默认 OFF 时仍沿用开发库，--database 参数仍可覆盖。此项只修改入口路径选择，不改变业务、数据库格式或终端菜单。

运行 scripts/package_p4.ps1：配置和构建两个 Release 入口，CMake install 放入 dist/JLU_InstantMessaging，windeployqt 整理 Qt DLL 与平台插件；补充同一 MinGW 的运行库、qt.conf、运行说明及第三方许可。部署不复制项目库、不删除已有 data；同时生成排除 data 和 .db 文件的便携压缩包。分享时使用不含数据库的 JLU_InstantMessaging_P4_Windows_x64.zip，首次运行自动建库。

本机已验证移动到含中文与空格的目录、移除开发 PATH 后真实启动及顺序共用数据库；尚未在另一台电脑实测。P5 通信与 P6 最终课程报告不属于本次 P4 交付。

## 7 卡片材质调整（2026-10-12）

账号三块、好友各分区、群列表与详情、登录表单统一使用 surfaceCard 属性。CardSurfaceLJY.h 的小函数给每张卡片添加独立 QGraphicsDropShadowEffect：模糊半径 20、向下 3 像素、灰绿色 QColor(34,70,52,30)。theme.qss 负责高不透明度乳白渐变、顶部高光和圆角，不用整块透明度效果，不模糊文字，也不实现实时背景模糊。

页面边缘及页签内容预留阴影空间，卡片间隔约 20 像素；卡片内列表、表格和页签底色透明以融合材质，输入框及选中行继续保留清晰底色。侧栏身份卡保持白色；提示条使用原样式和独立震动效果。账号、好友、群、登录相关 8 项 GUI 回归及实际控件截图检查通过，详见验收第 14 节。
