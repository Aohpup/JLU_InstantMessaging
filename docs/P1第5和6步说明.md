# P1 第 5 和第 6 步说明

启动方式更新（P2 第三批）：下方从注册开始的旧演示请使用 `jlu_im.exe --empty`；默认启动现已加载演示账号和群。

更新日期：2026 年 9 月 11 日。登录会话、菜单及 P1 第 7 步验收均已完成，详见 [阶段验收报告](P1第7步验收报告.md)。

## 阅读路径

1. domain/PasswordCredentialLJY.h：课设密码凭据，私有字符串保存测试密码并进行比较。
2. services/AccountServiceLJY.h：注册人员及首个服务、验证密码、维护原有账号规则。
3. services/ServiceLoginStateLJY.h 与 SessionManagerLJY.h：当前人员、当前服务和各服务确认状态。
4. ui/ConsoleAppLJY.h：数字菜单与输入输出。
5. main.cpp：创建上述对象并运行菜单。

正式调用链是 ConsoleApp → SessionManager → AccountService → Platform。菜单不持有可写的平台引用，也不接受手动输入的人员编号作为权限依据。

## 注册与密码

初次启动为空平台。注册时一次收集服务、姓名、生日、所在地、昵称和两次密码，全部完成后再提交。注册同时创建人员、凭据和首项服务；失败时回滚新人员及凭据，避免留下无法登录的账号。注册成功不会自动建立登录会话。

每个人员保存一份凭据，本人三个服务共用这份密码。内部人员编号和内部账号编号用于关联，登录使用服务类型及对外号码。没有凭据的底层测试人员不能直接登录，系统没有通过输入人员编号重设他人凭据的入口。

密码为 8 至 20 字节，仅允许 ASCII 33 至 126 的可见字符，即英文字母、数字和符号；不允许空格、中文、控制字符或其他非 ASCII 字符，不强制混合字符类别。开头仅提示“各项输入 0 可返回”，具体规则放在“设置密码”提示内。Windows 交互控制台逐键显示 *，支持退格删除；测试用输入流不把密码写到输出中。

注册使用 while 循环单独处理密码：格式不合格时立即提示重输，两次密码不一致时重新设置并确认。姓名、生日、所在地、昵称和所选服务保留，不返回主菜单。密码步骤输入单独的 0 仍取消本次注册；输入结束不创建账号。

2026-09-11 按课设要求简化：构造函数检查格式后将测试密码保存到私有 string；matches 使用 == 比较，不再调用系统密码接口。当前密码是进程内的明文演示数据，不提供读取接口，也不写入文件；不将此方案用于真实账号。长度、字符范围及菜单重输逻辑不变。

## 会话规则

| 操作 | 结果 |
| --- | --- |
| 首次登录 | 验证服务、对外号码和密码，只将本次服务设为已登录 |
| 其他已开通服务 | 显示待确认登录；不重复要求密码 |
| 取消确认 | 当前服务和原有登录状态不变，尚未登录的目标仍待确认 |
| 确认进入 | 将目标服务加入已登录集合并切为当前服务 |
| 切回本会话已登录服务 | 直接切换，原有服务登录状态保留 |
| 登录或切换未开通服务 | 拒绝，不隐式开通 |
| 登录后主动开通服务 | 创建本人账号，等待确认，不自动切换 |
| 修改昵称 | 只修改当前已登录服务的账号 |
| 微信／QQ 绑定 | 本人两个服务当前均已登录，或两个账号均曾用密码成功登录后绑定 |
| 统一注销 | 清空本会话身份、当前服务和所有服务登录状态 |
| 再次登录 | 重新验证密码，其他服务也须重新确认 |

会话已登录时拒绝另一次首次登录，须切换服务或先注销，防止身份悄然被覆盖。注销只影响当前 SessionManager；多个独立客户端会话彼此隔离。

## 菜单练习

在项目根目录执行：

```powershell
cmake --preset local-debug
cmake --build --preset local-debug
.\build\debug\bin\jlu_im.exe
```

1. 主菜单选 2，再选服务 1（QQ），输入测试姓名、生日（例如 2000-01-01）、所在地、昵称，以及两次课堂测试密码（例如 TestOnly123!）。首个 QQ 号码为 10001。
2. 主菜单选 1，选 QQ，输入 10001 和刚设置的密码。
3. 登录菜单选 3 开通微信，输入微信昵称；号码为 wx_20001，状态显示待确认登录。
4. 选 4 切换到微信，先选 0 取消，查看仍在 QQ；再重复操作并选 1 确认，进入微信。
5. 选 7 绑定微信与 QQ；选 1 查看资料和注册年龄，选 6 修改当前微信昵称。
6. 再开通微博，验证对外号码与 QQ 相同；服务切换后可以验证各服务中的用户昵称独立。
7. 登录菜单选 0 统一注销，再用微信号码及同一密码登录，查看 QQ、微博恢复为待确认状态。
8. 注销后在主菜单选 0 退出。

数字选项要求完整整数；小数、尾随字符、超范围值和整数溢出都重新提示。各项文本输入可输入单独的 0 返回，因此文本值 0 不用于姓名、昵称或密码。输入中断时退出并注销；未完成的资料修改和注册不会提交。

## 验证结果与边界

`ctest --preset local-debug --verbose`：三个测试程序通过，共 32 组场景。原有 12 组账号与日期测试保留；会话菜单 15 组覆盖密码验证、注册失败、匿名保护、首次认证、跨服务确认与取消、注销重登、凭据复用、多人隔离、绑定约束、资料修改和菜单流程。另有 5 组绑定历史测试验证分次登录、不同顺序及人员隔离。实际 jlu_im.exe 也通过中文输入脚本完成注册、登录、开通、确认、资料展示、注销与退出。

数据和凭据当前仅在内存中，退出后清空。无真实网络登录、密码找回、持久化、好友、群或数据库接入。AccountService 是可信的内部业务接口，其编号参数不是外部认证凭据；正式菜单必须通过 SessionManager。测试日期可固定，正常运行使用会话创建时的本机日期，跨日长时间运行的日期刷新留待后续完善。

新接口继续使用普通简体中文 `//`，优先注释头文件；界面功能验证不能用编译成功替代。第 5、6 步的针对性验证不等于已完成顺序 7 的完整课程验收。

本次密码输入调整扩展现有场景，覆盖 8/20 字节边界、全部字节的允许范围、连续无效密码及两次不一致后的资料保留、超长输入、重输时取消和输入结束。

2026-09-10 输入调整：生日输入后立即通过会话调用账号业务校验，用 while 循环重输；注册与修改资料均适用。覆盖格式、年月日范围、闰年、未来日期、已有账号申请日期限制，以及取消、输入结束和资料保留。界面统一使用“用户昵称”。该次输入调整扩展了现有菜单测试组，当时共 27 组；随后加入 5 组绑定历史测试，目前合计 32 组。

密码提示分为两处：ConsoleAppLJY.cpp 的设置密码提示在输入前显示；PasswordCredentialLJY.cpp 的校验异常在输入不合格时显示。修改其中一处不会自动修改另一处；本次已将输入前提示同步为用户采用的“大小写字母、数字和符号”措辞。

控制台暂停：ConsoleAppLJY::run 在一次菜单操作完成后统一调用 pressAnyKeyToContinue，注册、登录、查询、开通、切换、修改、绑定、注销、说明、取消返回以及整项操作失败均适用。提示为“>>>按任意键继续”，按字符键、回车、方向键或功能键即可继续，不必额外回车。生日、密码、数字选项的局部重输不暂停；退出和输入结束不暂停。Ctrl+C 在暂停时忽略，Ctrl+Z 仍可结束程序并注销。

暂停仅用于真实 Windows 控制台；管道或测试字符串流自动跳过，避免消耗下一条菜单指令。暂停前清理旧键盘事件，结束后恢复原输入模式。

2026-09-10 绑定调整：同一人员的 QQ 与微信均曾用密码登录成功后，可以注销再登录任一服务直接绑定；记录属于平台账号，跨 SessionManager 实例仍有效，程序重启则清空。开通、密码错误以及取消确认不记录为密码登录；历史不改变当前服务的待确认状态。

Ctrl+C 调整：main 注册只处理 CTRL_C_EVENT 的控制处理函数；普通输入改由 ReadConsoleW 读取，遇到中断继续读取，密码及暂停循环忽略 Ctrl+C。VS Code 有选择时由终端复制；无选择时不退出。正常退出仍用主菜单 0。
