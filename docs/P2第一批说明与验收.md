## 1 本批实现

| 文件或类 | 职责 |
| --- | --- |
| [FriendRelationLJY.h](../src/domain/FriendRelationLJY.h) | 保存两个账号编号及双方各自备注；一条记录表示双向好友 |
| [FriendManagerLJY.h](../src/services/FriendManagerLJY.h) | 添加、删除、备注、列表、资料查询以及归属和同服务校验 |

| [SessionManagerLJY.h](../src/services/SessionManagerLJY.h) | 从登录状态取得执行者，只在当前服务中解析对方号码 |

新增两个类均有独立 .h/.cpp 文件，普通简体中文 // 注释主要写在头文件。当前正式源码共 14 个类、4 个枚举。所有新增 cpp 显式加入 CMake。

调用顺序：main → ConsoleAppLJY::run → friendMenu → SessionManagerLJY → FriendManagerLJY → PlatformLJY 中的关系。

## 2 关系与权限规则

- 关系使用服务账号内部编号，不使用姓名或昵称，也不把人员编号当作账号编号。外部菜单输入对方在当前服务的显示号码。
- 同一对账号只保存一条记录，所以添加、删除对双方同时生效。A→B 和 B→A 不能重复添加。
- 同一人员的 QQ、微博即使显示号码相同，好友关系仍分开；微信与 QQ 的关系也不会自动同步。
- 双方备注分别保存。A 修改对 B 的备注不会改变 B 的备注、姓名、生日或用户昵称。
- 备注允许中文，非空最多 120 字节，不允许全空白或控制字符；留空清除备注，单独输入 0 取消本次操作。
- 添加前展示目标号码与用户昵称，确认后提交；采用已约定的课堂简化流程，不增加好友申请审批。
- 查询完整人员资料、改备注和删除均要求已有好友关系。添加前的账号预览只展示号码与用户昵称。
- 不存在账号、自我添加、跨服务、重复关系、操作他人账号，以及未登录/注销后操作均被拒绝。
- 删除清除双方关系和备注；重新添加时备注为空，其他服务的关系不受影响。
- 底层 FriendManager 的人员/账号参数供可信内部调用；界面只能经会话取得执行者，不能手填执行者编号。

## 3 如何使用

在项目根目录构建并运行：

```powershell
cmake --build --preset local-debug
.\build\debug\bin\jlu_im.exe
```

登录后选择 **8 好友管理**：

```text
1 好友列表
2 查询好友资料
3 添加好友
4 修改我的备注
5 删除好友
0 返回主菜单
```

普通操作完成或失败后按任意键继续，仍停在好友子菜单；选择 0 直接返回主菜单，不再要求额外按键。Ctrl+C 保护和密码星号继续有效。

建议演示：

1. 在同一次程序运行中，先注册测试甲和测试乙，均选择 QQ，记录各自号码。空平台按此顺序注册时通常为 10001、10002；以程序实际输出为准。
2. 登录甲，选 8 → 3，输入乙的 QQ 号码，选 1 确认。再选 4 设置“同学乙”，选 2 查询乙的资料。
3. 选 0 返回主菜单，再选 0 注销。登录乙，选 8 → 1，应看到甲，乙的备注仍为“未设置”。
4. 乙给甲设置自己的备注，再注销回甲，确认甲的备注没有改变。
5. 任一方删除另一方并确认，换另一方查看，关系也已消失；重新添加后双方备注均为空。

目前没有预置用户，演示初始化属于第三批。数据仅保存在内存中，退出程序会清空关系及账号。
