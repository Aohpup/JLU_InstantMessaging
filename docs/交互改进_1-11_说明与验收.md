## 群名单如何更新

`GroupRosterLJY.h` 是一个简短的文件合并函数：取得名单文件锁 → 读取最新名单 → 删除本次确实移除的账号 → 加入本次新增的账号 → 原子替换文件。昵称/颜色变化只更新仍在最新名单中的成员，不把已经被删除的人加回来。

`GroupMessagesPageLJY` 记录本机操作前的名单，群操作成功时比较前后差异。普通旧窗口的“前”和“后”相同，所以不会重新添加已经由其他窗口移除的人。服务端每秒读取名单变化，并断开已移出的成员；同时广播完整名单供所有连接显示。

本机多个客户端共用 `%LOCALAPPDATA%/JLU_InstantMessaging/group-server` 的房间名单与日志，各自业务数据库仍独立。完整名单广播可用于本机、局域网临时房间和远端持久服务；**本轮自动合并文件针对同机持久服务**。远端独立服务的 `--members` 文件仍需由服务电脑维护；这不是集中式账号、好友与群管理服务，也不会将另一台电脑的全部业务数据库自动同步过来。

## 自动保存规则

页面修改业务成功后发出 `changed` → `MainWindowLJY::markChanged` → 保存回调 → `SqliteStorageLJY::save` 的事务。注册成功也走同一入口。未提交的输入框仅是草稿，不会自动当作有效资料写入。

保存失败：独立保存状态持续显示未保存提醒，底部出现“重试自动保存”，内存改动保留。保存成功才显示成功落库；退出失败仍可重试、取消或明确放弃。没有业务改动时关闭窗口不会再用旧快照覆写数据库。注销前有保存失败则先重试，失败时留在当前账号。

图形端采用上述规则；原终端保存菜单保留。多个客户端做对话演示仍各用独立业务数据库；自动保存没有把整个项目改为共享数据库的多人编辑系统。

## 后台群消息与未读

登录当前服务后，页面为本人各群维护接收连接；非选中群只收消息并落库，不绘制气泡。选群时切换前台展示，其他群仍接收。切换服务或注销时关闭旧身份连接。内存练习模式同样接收，但关闭后不保留。

群历史仍使用 `group_chat_messages`；新表 `group_chat_read` 只记录“服务、本人账号、群号、已读本地行号”。服务端重放按已有消息唯一键去重，不重复增加未读；本人发送的消息不计入未读。在聊天页看到最新消息时清零，翻看旧消息、设置展开或页面隐藏时继续累计。正常模式重启后保留群已读位置。

私聊提醒基于现有真实连接收到的消息，按服务、账号、好友计数，正常模式保存在数据库旁 `.unread.ini`。本轮没有把私聊改成面向所有好友的中心消息服务器。好友申请角标来自当前平台已加载的待处理记录，仍沿用现有申请业务。

自动启动群服务时明确不继承主程序句柄，避免后台进程持有私聊套接字而使对端迟迟看不到断开。

## 本轮新增交互的使用与原理

### 固定保存状态（7）

操作广播仍使用原有红色错误条或普通黑字。其下方、数据库路径上方另设固定状态行：

- 成功提交后显示“已自动保存”；内存练习模式明确提示关闭后不保留。
- 业务保存失败显示“有未保存修改”，聊天落库失败显示待保存条数，并提供重试按钮。
- 账号编辑展开时另标记“账号表单待提交”，提醒输入框中的草稿还需要点击提交；不会将草稿当作已经保存的资料。
- 连接、等待、同步进度留在聊天顶部；失败仍可进入红色广播，但不会擦掉独立保存状态。

`MainWindowLJY::updatePersistence` 汇总业务 dirty 标记、两类聊天待保存队列及账号编辑状态。沿用现有 500 毫秒界面刷新，不增加后台数据库轮询或新的保存层。

### 搜索与最近列表（9）

四处列表顶部有独立搜索框，输入即筛选，清除即可恢复；没有匹配项时明确提示。筛选只隐藏行，不删除好友/群，不停止当前聊天，不更换正在操作的对象。通过资料入口跳转到指定好友或群时，会清空对应搜索，保证目标可见。

私聊摘要沿用头像、昵称及账号行，增加一行时间和正文预览；群聊摘要显示发送者和正文。多行正文压成一行并截断，完整正文仍在气泡中。按最后消息时间倒序，同一时间按号码稳定排序；从未聊天的对象在后。收到、发送消息会更新摘要与排序，不自动切换当前会话。

启动时仅按各联系人/群读取最近一条记录用于摘要，不把全部历史读入内存；消息到达时直接更新缓存。数据库读取失败不妨碍打开联系人，聊天历史仍有现有的重试入口。摘要使用当前客户端已收到并保存的消息，未增加私聊中心服务器。

### 历史阅读（11）

选择会话初次加载最近一页；有未读时不因选中会话而清零。“加载更早消息”仍按原规则加载一页并定位到该批旧内容。向上滚动后，新消息追加在末尾，当前滚动位置不变。聊天记录与输入框之间的浅色横条显示未读数量，点击定位到最早未读，必要时自动补读更早的一页；仍有未读内容在下方时不清零，阅读到末尾后恢复跟随并清除未读。重新进入当前群以及同一私聊页面刷新也保留阅读位置。

日期以本机时区显示，不修改消息时间或数据库。保留原头像、气泡、长消息展开及发送状态。主动发送消息后回到末尾，便于确认自己的发送结果。延迟布局定位带简单的序号：点击未读横条后，较早一轮重排不再撤销这次定位。

## 2026-10-20：未读提醒和私聊连接调整

### 本次行为

- 好友行、群聊行及私聊/群聊页签统一用红底白字的未读数字；超过 99 显示 `99+`，横条仍显示实际数量。
- 浏览其他好友只切换页面和草稿，原好友的连接仍收发消息。后台收到的消息归到原好友的内存、SQLite 记录和未读数中，不显示在新好友的气泡里。
- 返回原好友即可继续发送。点击新好友的“开始聊天”才停止旧连接，并按已保存设置连接新好友；浏览其他好友时，原连接的等待/重试也保留。更多设置里的“断开连接”仍可主动停止当前连接。
- 未连接的新好友可以编辑草稿，但不能把草稿误发给原好友。注销、切换服务、删除实际连接的好友及关闭程序仍按原流程停止连接。
- 原“回到最新”按钮替换为聊天区内、输入框上方的浅色全宽横条：`N 条未读消息 · 点击查看最早未读`。无未读时隐藏。
- 点击定位第一条未读气泡的开头。未读超过当前 100 条历史页时，自动向前补读；未读全部进入末尾视野后清零，否则保留提醒，继续向下阅读。

### 代码阅读

1. `MessagesPageLJY.h` 的 `selected_` 与 `connectedPeer_`：分别表示浏览对象和连接对象。
2. `selectFriend → beginConnection → startConnection`：浏览保留连接，明确开始才切换。
3. `pollEvents → storeMessage/updatePreview`：按连接对象接收、保存和更新未读；只有当前浏览对象相同时才追加气泡。
4. `ListPresentationLJY.h`：红色数字、浅色横条、群列表行和消息位置的共用小函数。
5. 两个聊天页的 `jumpToUnread`：私聊按保存的未读数倒数接收消息，群聊通过 `GroupChatHistoryLJY::firstUnread` 查询已读位置之后的第一条；需要时补读历史页。
6. `GroupMessagesPageLJY::fitBubbles`：测量前对正文、昵称、时间应用字体，避免首次布局与显示后行高不同而导致跳转偏移。
